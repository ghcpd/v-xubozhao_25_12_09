- scikit-learn, SciPy, and Matplotlib often require compiled wheels or platform-specific build tools (e.g., MSVC on Windows).

- Keeping them optional avoids blocking CI or developer setup for basic runtime/tests. For reproducible analytics installs, use conda/conda-forge or CI images that include those compiled wheels.

## ⚖️ Upgrade rationale / compatibility notes
- numpy 1.18 → 1.26.x
  - Reason: Newer performance, bug fixes, security updates. Provides modern dtype & API improvements.
  - Warning: numpy 2.x introduces breaking changes for some libraries — I pinned to 1.26.x to stay stable across Python 3.10+ and to avoid unnecessary incompatibilities.
- pandas 1.1.5 → 2.2.3
  - Reason: Pandas 2.x includes important bug & security fixes and performance improvements.
  - Breaks: Pandas 2.x removed some deprecated behavior — code that relied on old string-dtype defaults might need small edits.
- scikit-learn 0.24.1 → 1.4.2 (moved to analytics)
  - Reason: Multiple API changes and large improvements since 0.24. 1.x is the maintained, secure major line.
  - Caveat: scikit-learn often requires platform build tools; moved to optional list to avoid breaking basic tests.
- pytest 5.4.3 → 7.4.4
  - Reason: Pytest 7+ has many new features and better ecosystem integration; also security and bug fixes.
  - Note: Upgrading tests might need small fixes if users used old pytest behaviours.
- fastapi & uvicorn updates
  - Reason: Upgrade for performance and security patches. FastAPI and uvicorn also follow a steady maintenance cycle.
